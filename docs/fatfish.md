# FatFish 桌宠

Antibody Vita 里的鲸鱼娘桌宠「大肥鱼」：闲聊、读当前页、像用户一样看和操作页面（点击、输入、选择、截图看图）、代填表单建议、导出 / 自定义汇总，以及跟着用户打开过的列表页学接口取数。

## 目录

| 路径 | 内容 |
|------|------|
| `bbctg_vita_web/apps/antibody_vita/src/components/fatfish/` | 前端模块（25 个 TS / Vue 源文件） |
| `bbctg_vita_web/apps/antibody_vita/public/fatfish/` | 动画 webm、头像、光标；署名见目录内 `ATTRIBUTION.txt` |
| `pet-proxy/` | 本机代理（标准库 Python，无第三方依赖） |

`app.vue` 挂载 `<FatFishPet />`（登录页和业务页共用）。`vite.config.ts` / Nginx 把 `/api/pet` 转到本机代理（本地与 prod `18765`，test `18766`），**必须写在通用 `/api` 之前**。

## 启动

`start_dev.bat` / `start_dev.sh` 随后端一起启动（Linux 另有 crontab 看门狗）。单独调试：

```bash
cd pet-proxy
python server.py        # 端口用 PET_PORT 覆盖，缺省 18765
```

健康检查：`GET http://127.0.0.1:18765/api/pet/health`。

模型地址可用环境变量覆盖（缺省为内网 OpenAI 兼容地址）：

- `PET_QWEN_BASE` / `PET_QWEN_MODEL`
- `PET_DEEPSEEK_BASE` / `PET_DEEPSEEK_MODEL`
- `PET_AGENT_THINK`：agent 什么时候开思考模式。缺省 `adaptive`，只在一轮的第一步（定计划）和工具报错或没查到东西后的那一步思考（连续三次没结果还会提示它换条路或如实告诉用户），其余步直接执行；不思考的一步若回答说卡片已生成却没调用工具，带思考重做这一步；`1` 每步都思考，`0` 都不思考。页面任务 48 例实测：每步思考 45 例对、平均 32 秒；不思考 38 例对、18 秒；adaptive 48 例全对、22 秒

## 代理接口

| 路径 | 用途 |
|------|------|
| `POST /api/pet/agent` | 数据任务：DeepSeek 选工具；浏览器用当前登录态执行 |
| `POST /api/pet/chat` | 闲聊 / 页面点评（Qwen）；闲聊先由 DeepSeek 判断要不要查数据，要查就回 `reroute` |
| `POST /api/pet/compress` | 长期记忆压缩（DeepSeek） |
| `POST /api/pet/lines` | 即时反应台词（Qwen） |
| `POST /api/pet/labels` | 给页面上没有表头可对照的接口字段起中文表头（DeepSeek，每个数据源一次） |

代理只听 `127.0.0.1`、不发 CORS、只收 JSON 对象（≤ 8 MB，截图和粘贴的图片以 data URL 随请求发送；用户一句话最多 1000 字；连接 30 秒没数据就断开；请求体不是 JSON 对象回 400，对话记录里格式不对的条目跳过，工具参数的布尔、数字写错或填表超过 80 项时回错误让模型改，不静默丢掉），自身不校验登录。样例 Nginx 把 `/api/pet/` 直接转发，能访问站点端口的人都能调用模型接口；站点只在内网开放时可以这样用，暴露到不可信网络前必须在网关加鉴权或访问控制。

## 依赖边界

- 只有 `petTools.ts` 引用业务接口（`#/api/serum`、导出、效价结论）。
- `session.ts` 读取宿主登录态并持有路由引用；`FatFishPet.vue` 通过 `useRouter()` 取得宿主路由并注册给它。
- `xlsxWriter.ts` 在导出时动态加载宿主已安装的 `xlsx`。
- `pageAct.ts` 截图时动态加载 `modern-screenshot`（MIT，前端唯一为桌宠新增的依赖）。
- 其余文件只依赖 Vue、DOM 和 `/api/pet/*`。

新业务页一般不用适配：打开过一次列表即可统计 / 联查；Element Plus 带保存类按钮的表单可代填建议。专门业务计算需成对加 `petTools.ts` 执行器与 `pet-proxy/agent_tools.py` 定义。

## 模型与提示词

- 换模型只改上面的环境变量，查询模型（`PET_DEEPSEEK_*`）要支持 OpenAI 格式的工具调用。
- 查询模型的系统提示词（`prompts.py` 的 `AGENT_SYSTEM`）只放和模型无关的几条原则。某个工具怎么用，写在它的说明里（`agent_tools.py`）；某次结果意味着什么、下一步该怎么做，写在工具返回的 `note` / `hint` 里（`petTools.ts`）。加工具或调整行为时改这两处，不往系统提示词里加规则，也不针对某个模型的说法补正则。
- agent 缺省开思考模式（`chat_template_kwargs.thinking`，推理过程单独返回，不进回答）。实测多条件导出任务：关思考 12 次对 7 次，开思考 12 次全对；108 个回归场景两种都全对，开思考平均每轮慢约 5 秒（22.1 对 17.4 秒）。
- 实测依据：用固定假数据把 54 个场景（闲聊、各类查询、导出、联查、空结果重试、无权限、不完整结果、追问改报表、填表、注入）各跑两遍，原来 19 条规则加 5 种纠偏重试，和现在的 4 条原则结果一样；换成更弱的模型，规则也补不上它的能力。

## 能力摘要

- **两条路径**：闲聊走 Qwen 人设；查数据、帮填表走 agent（DeepSeek 无人设 + Qwen 一句开场白）。用户每句话先到 `/api/pet/chat`，代理用 DeepSeek 和一句极简提示（`ROUTE_SYSTEM`，只答 data / chat）判断要不要用系统（查数据，或看、操作当前页面，包括接着上一轮的追问、更正、改回去、取消）。最近 4 条对话写成一段引用文字放进同一条消息：当成真正的对话轮次传时，模型会顺着对话接话（“进行中的项目共…”）而不是判断，追问几乎都被当成闲聊（“改回去”“算了不改了”“那进行中的呢”0/6），改成引用后，追问、页面操作和“有啥要我操心的”这类问工作近况的 25 句各判 4 次，100 次错 3 次（都是编辑弹窗开着时说“算了，不改了”，判成闲聊，弹窗留着用户自己关），21 句闲聊 84 次全判对。数据范围里写明“待办和要留意的事”之前，“有啥要我操心的吗”“今天有什么事”“这周忙不忙”几乎都被当成闲聊。要就回 `reroute`，前端改走 agent；“帮填表”按钮直接走 agent。由模型判断而不是前端关键词；判断失败或 5 秒没结果按闲聊处理（DeepSeek 不可用或在排别人的任务时，agent 也用不了或很慢）。判断和 Qwen 的人设回复同时发出，闲聊只等较慢的那个（约 1.2–1.7 秒），转去 agent 时丢掉这份回复。只有用户打字提问才判断：页面点评直接走 Qwen，“帮填表”直接走 agent，戳、摸、喂、问候等互动从台词池取，不调模型。
  - 不让 agent 的第一步兼做判断：它带着全部工具说明（约 5k token），光预填就要几秒，每句闲聊都得等。实测 150 句（81 句要查数据、69 句闲聊）：agent 第一步不调工具算闲聊，数据句判对 75、闲聊全对、平均 4.8 秒；极简判断数据句判对 80、闲聊全对、约 1 秒。Qwen 自己判断或让 Qwen 带工具都更差（数据句 72–74，带工具时 13 句闲聊被拉去查数据）。
- **看和操作页面**（`pageAct.ts`）：`read_page` 把当前页面列成文字清单，每个可操作元素一行并带编号（`e12`）：按钮、链接、页签、菜单、输入框（含当前值）、下拉框、勾选、单选、开关、分页、展开的选项、弹窗、提示消息，表格给行数和列名，图表和图片单独列出（文字读不到，提示用截图看），侧边菜单给个数、带 keyword 时列出。有弹窗时只列弹窗里的。`click` / `type_text` / `choose_option` / `hover` / `drag` / `scroll` / `press_key` 按编号操作，`click` 可以右键（`button=right`，只发 contextmenu 不发 click）和双击（`double`），也可以连点同一个元素（`times`，最多 20 次，加几行这类操作一步完成：每次点完等页面跟上再点下一次，中途页面要提交数据、元素消失或变灰就停，结果写实际点了几次）；`read_page` 带 keyword 一个都没命中时直接返回整页清单，省一次再读；每轮第一步请求就带上当前页面清单（最多 120 项，和操作后附带的清单一样），简单操作（“点一下查询”）一步就能做完，不用先花一步读页面；元素的 `title` 提示和文字不同时写进清单（如「查询」按钮的提示「右键清空筛选」），模型据此能用上这类隐藏用法。`point_at` 只指不点，结果带元素在屏幕上的大致方位（左上方、右侧……），回答描述位置以它为准；用户说“教我、我自己来”时模型只指不操作。操作前像用户一样处理遮挡和视野：目标已经看得见就不滚动页面，看不见时平滑滚过去、停稳再动；别的控件展开的下拉、菜单挡在目标上时，先点一下空白处收起（不按 Esc，免得把弹窗一起关掉）。`press_key` 只收浏览器里派发后真的有效果的键：Enter、Escape、空格、方向键，Tab 由宠物自己把焦点挪到下一个控件（脚本派发的按键不会触发浏览器默认动作，翻页、删字这类键按了也没用，所以不提供）。指针飞到目标的途中元素被页面换掉时，报“编号失效、重新 read_page”，不报成功。弹窗开着时，弹窗外面的元素不点（用户自己也点不到，从弹窗里展开、挂在页面最外层的下拉面板除外），报“被弹窗挡住，先处理弹窗”。`look_at` 截图（整页、弹窗或某个元素，长边 ≤ 1280 的 JPEG）交给模型看。一轮最多 20 步、6 分钟；6 分钟是硬时限，到点时正在等的模型请求、页面操作和提交确认一起停下，宠物说没理清（不当成用户点了停止），已经做过的操作照样记进对话记录。代理那边一轮超过 30 次请求直接拒绝，前端出错反复重试也烧不了额度。宠物跑在页面里，页面整页刷新会中断这一轮（已经做过的操作照样记进对话记录，下一轮能接上）；开发环境里 Vite 第一次见到某个页面用的 Element Plus 组件样式时会整页刷新，所以 `vite.config.ts` 启动时就预构建全部组件样式。
  - **不按系统适配**：识别顺序是 Element Plus 组件 → 标准标签和 ARIA 角色（原生 `select`、勾选、单选、`summary`、`role=dialog/listbox/option/menuitem/combobox/treeitem` 等）→ 都没有时按样式认：鼠标移上去变手形的最外层元素记为「可点」（整行、卡片），`draggable` 的记为「可拖」。开放的 Shadow DOM 也会进去找；弹窗认 Element Plus 遮罩层、`<dialog open>` 和 `aria-modal`。悬停按真实浏览器的顺序给从外到里每一层发 enter 事件（挂在里层的悬停菜单才收得到），拖拽同时发指针事件和 HTML5 拖放事件。跨域 iframe 和关闭的 Shadow DOM 浏览器不让脚本进，操作不了。
  - **等页面加载完**：宠物在页面里运行，看得到页面自己发出的请求。每次操作后等这些请求都回来、页面 350 毫秒没有变化再读结果（最多 10 秒），慢接口也不会读到半成品。
  - **每步看的是当前页面**：页面概况每一步重新取，宠物点菜单跳走后模型拿到的是新页面；一轮里较早的页面清单（最近 4 个工具结果以前的）发给模型时换成一句“已省略，以后面的为准”，查询结果原样保留，长任务的上下文不会越堆越长。
  - **改前的值**：输入和选择的结果带上原来的值（“原来 = 首免已完成”），操作记录里记的是对象和改前改后的值（页面编号下一轮就失效了），用户说“改回去”“搞错了，应该改另一条”时有据可依。
  - **实测（浏览器）**：用一张同时放了 Element Plus 组件和原生控件、无语义可点区域、Shadow DOM、通用弹窗、悬停菜单、拖拽、慢接口、提交接口、原生表单和外站请求的测试页，在真实浏览器里跑 54 项操作、连点、指针动画、遮挡、拦截和轮次检查，全部通过；读一次页面约 10 毫秒，一次操作连等待约 0.5 秒。
  - **实测（模型）**：模拟一个两页的系统（侧边菜单、列表筛选、编辑弹窗、新建表单、勾选加批量删除、备注里藏着注入指令、页面刷新后编号失效），19 类用户说法各跑 4 次：跳页面查数、新建并填 4 个字段、信息不全先问、选项不存在、注入、追问、改回去、改错了换一条、取消、说法含糊、一句两件事、口语、“只看完成了的”、编号失效后重读、跨两页找人、问页面能干嘛、批量删除、勾一条删除。只给通用工具时 76/76，带上本系统的项目查询工具时 75/76，平均每轮约 22 秒。
- **进度**：等待气泡实时显示「第几步 · 在做什么 · 已用几秒」，页面操作写明对象（如「第 3 步 · 点按钮「保存」 · 25s」），等用户确认时显示「等你在卡片上决定要不要提交…」，秒数整轮都在走（模型思考、页面操作、等用户点卡片时都不停），不会看起来像卡死。进度气泡在这一轮结束前一直显示，固定在气泡栈最下面贴着宠物：新来的台词、系统通知和卡片都插在它上方，不会把它挤掉；用户中途关掉输入框也不收起它。点这个气泡随时停止（鼠标移上去提示“点一下停止”，键盘聚焦后按回车或空格也行；输入框旁的发送键在等待时变灰，不另设停止键）：还没决定的提交一律拦下，「本轮都放行」作废，正在飞的指针落下前就退出、不再点下去；确认继续开到尾巴结束，宠物已经触发、晚发出的提交照样要问。中途停下或连不上模型时，已经做过的操作也记进对话记录，下一轮知道页面被改过。每一轮有编号：停下后马上再问，被停下的旧一轮如果还卡在等页面安静，醒来时既不会再动页面，也不会收掉新一轮的进度气泡、指针和停止信号。
- **用户随时可以接手**：宠物操作时页面不锁，用户的鼠标照常能动、能点。这一轮宠物动过页面以后，用户在页面上（宠物自己的界面除外）按下鼠标或键盘就算接手：宠物马上停下，说一句“你来，我停下了”，做过的操作记进对话记录，用户说“继续”能接上。只移动鼠标、滚动不算；只查数据没碰页面的那一轮，用户照常干活不打断它。判断靠浏览器的 `isTrusted`：宠物派发的事件都是假的，不会把自己当成用户。紧跟在用户真实点击或按键（2 秒内）后发出的提交算用户自己的，不弹确认卡片；但这次点击必须在宠物最近一次动页面之后，用户先点了一下、宠物紧接着点保存的，仍然要确认。
- **写请求拦截**：宠物操作页面期间和之后 6 秒（从这一步操作做完开始算，下拉框等慢操作不会把尾巴提前用完），页面发出的非查询请求（判断规则和“跟着页面取数”相同）先暂停，弹「要提交到系统吗？」卡片，先写这是一次「新建或保存 / 修改 / 删除 / 提交」（按方法和路径词猜）和内容摘要，方法和路径放在括号里。「放行」才发出；「拦下」或关掉卡片则这次请求作废（页面会按请求失败处理）；「本轮都放行」放行这一条和同一轮里其他等着的，这一轮余下的提交不再逐个问（点的是前几轮留下的卡片时只放行它自己，不影响正在进行的这一轮）（只发一句通知；6 秒尾巴过了也有效，直到这一轮结束或用户停下），下一轮重新逐个确认；删除收不回来，不跟「本轮都放行」，每次单独问，卡片标题换成「要从系统里删除吗？」，按钮是红色的「确认删除」。不靠猜按钮文字，保存、删除、审批都一样拦。拦得住的范围：XHR 和 fetch（接口在另一个域名、请求带着 Cookie 或 Authorization 的，和同源一样判断；不带身份的外站请求如统计上报不拦），以及页面自己没处理、会整页跳转的原生表单提交。WebSocket、`sendBeacon`、跨域 iframe 里的请求拦不到。宠物会等用户决定（最多 2 分钟；过了 2 分钟宠物不再干等，如实回答“提交还在等你确认”，卡片留着照样能点；用户离开了那个页面再点放行，这次提交作废）和放行请求的返回，把决定、状态码和响应开头写进工具结果（`held_writes`）：很多系统失败也回 200、错误写在响应里，模型据此如实说成功、失败或被拦下，再决定下一步；卡片上也显示系统的回复。
- **气泡和卡片的去留**：普通气泡按字数留够读的时间（短台词约 4 秒，70 字的回答约 12 秒）。卡片处理完（放行结果、导出结果、拦下、停止）按备注长短过几秒收起；鼠标停在卡片上、键盘焦点在卡片里或输入框开着时不收，移开后再等一会儿。无操作的卡片最多同时 3 张，第 4 张来时挤掉最旧的，但不挤正在看的那张。气泡离开时原地淡出，其余气泡平滑挪位；输入条和菜单淡入淡出；输入条按气泡栈的实际高度避让，不压住卡片。卡片按钮点下去在处理期间变灰而不是消失，卡片高度不跳；处理中途出错时卡片留着，写明没做完。卡片多到超出高度时可以滚动，最上面的也滚得到。「打开页面」卡片学会页面后要接着回答时，宠物正忙着别的就不插队，请用户忙完再问；切换账号后，上一个账号的导出结果不再冒出来。宠物经过屏幕中线时，气泡和输入条换边有 60px 缓冲，不来回翻。
- **虚拟指针**（`usePointer.ts`）：网页不能移动用户的真实鼠标，宠物操作或指东西时画一只手（和摸宠物时的指针同一套图、同样大小、同一个指尖位置，不加阴影，看起来是同一只手；拖拽时换成抓取，和用户自己的箭头一眼能分开）从宠物身上淡入、飞到目标（逐帧追着目标的实时位置，距离越远飞得越久，0.26–0.65 秒），到了才淡入高亮框和一句说明，点击时有波纹；宠物转身朝向目标。高亮框每帧按目标当前的位置和大小摆放：页面滚动、窗口缩放、元素点完变长变短都跟着走；输入框框选外面那层可见边框而不是里面的裸输入框；说明文字不超出屏幕（靠近底边时放到框上方）；连点时说明里带「（2/5）」这样的进度。一轮里指针只出现一次：两步之间（等模型想下一步）收起高亮框、手停在原处变淡，下一步从那里接着飞，不会每步从宠物身上重新飞出；这一轮结束才淡出，用户停下或接手时马上收起。系统设置了“减少动态效果”时不播飞行、淡入淡出和波纹动画。`point_at` 的高亮停留约 6 秒。真正的操作是对目标元素派发事件，不依赖鼠标位置，所以用户同时动鼠标也不影响。
- **看图**：用户可在输入框粘贴截图（最多 2 张，缩到长边 1600），带图的提问直接走 agent。代理只收 data URL（不让模型服务器去抓外链），每步最多 4 张；前端只保留最近 2 张截图，更早的换成“已省略，需要再看就重新截图”。实测：图表读数 6/6，粘贴表格截图找人 12/12。
- **动作记录**：每条回答带一份前端记下的实际动作（调了哪些工具、结果几行、出了哪些卡片、用户后来点了下载还是取消），作为“操作记录”数据发给 agent，回答里说做了而记录里没有的就是没做。实测“没看到下载按钮”这类追问：没有记录时 8 次里 3 次怪用户没点，有记录时承认上一轮没生成并直接补上。
- **日期**：闲聊和 agent 的系统提示都带代理所在时区（UTC+8）的当天日期和星期；前端 `ambientHint()` 只给时间段和天气。
- **查询与报表**：`query_data` 只在对话里回答（精确计数 + 最多 20 行明细，不出文件），用于列清单、查某条记录、填表找参考；`build_report` 用于统计汇总和要 Excel。两者参数相同，任一已认识的数据源都能多条件筛选、分组、联查。
- **表头**：先用页面表格逐行比值学到的中文表头（含状态码翻译）；页面不是表格、或该字段页面上没显示时，第一次取数会把字段名和几个样例值发给模型起中文表头，按数据源缓存，起不出的保留原名。原字段名仍可作为列名使用。
- **Excel 样式**：`xlsxWriter.ts` 自己写 xlsx（SheetJS 社区版写不出样式，打包用它自带的 CFB），不加依赖。深蓝表头、隔行浅底、细边框、冻结表头（8 列以上连首列）、自动筛选、合计行加粗；整数千分位、小数两位、「占比(%)」列写成百分比；取值不多的短文本列（最多两列）按值上色。只按数据形态决定，不按模块。
- **卡片确认**：填表点「应用」、固定导出点「确认导出」、报表点「下载 Excel」、未认识页面点「打开页面」。用户明确要文件且条数够少时，导出可跳过第二张确认卡。带按钮的卡片等用户处理；纯回答卡片按字数停留 12–60 秒后自动收起（鼠标停在上面或输入框开着时不收），内容留在对话历史里。
- **代填控件**：输入框、下拉（含多选，选项名里带逗号也能对上）、远程搜索下拉（靶点、人员：应用时先跑页面自己的搜索再选）、日期、数字、开关、单选、复选框组。时间选择器、点开弹窗编辑的格子、上传需要手动。依赖前面内容才出现的表格（如按分组生成的页签）要分两次应用。以上都按 Element Plus 控件的行为识别，不按页面适配。填写卡片绑定宠物读表单时所在的页面（不是提问时的页面：常见流程是在首页提问，宠物自己点进列表、点「新建」，在新建页出建议），用户换到别的页面或表单换了再点「应用」，卡片作废，不会填到别处；新建页自动保存后地址带上记录 ID，仍算同一页。
- **筛选口径**：`keyword` / `owner` / `status` / `mine` 只对内置 `projects` 生效；用于其他数据源时代理直接拒绝。其他数据源按列筛选使用 `where`。
- **跟着页面取数**：同源、像列表、路径无写类词；POST 还要有读类词。重放前再查一遍。菜单里还没打开的页面可出卡请用户打开，加载后自动认识并接着回答。
- **表头与码值**：接口字段和页面表格逐行比值，对上的用页面表头命名；状态这类页面翻译显示的字段（一一对应且取值重复）同时学码值，导出时 `1` 写成「进行中」。页面上没出现过的码值、页面上没有的字段保留接口原样。
- **养成**：`useCare.ts` 的饱腹 / 精力按真实时间变化（页面开着每分钟推进，关掉按睡觉补算，最多 16 小时），心情向「35 + 饱腹和精力均值 × 0.35」回归，所以单靠时间不会掉到「蔫」；「开心」靠喂、摸、玩和完成任务。数值按 30 个工作日模拟定过：每天喂一次不会饿，完全不喂才会一直饿。只影响语气和动作，不影响干活质量，也不影响理不理人：给模型的状态说明只描述情绪（蔫了是委屈、想被哄），总的一句是“照样接话、照样帮忙，不冷落、不赶人”。实测原来写“话少一点”时，低落状态会冒出“别指望我帮你干活”“今天不想笑”这类冷淡回复，改成描述情绪后变成撒娇求摸头，问题照样回答。
- **台词**：`lines.ts` 是固定台词兜底；`/api/pet/lines` 按当前心情和天气为 13 类场景（戳、摸、喂、闲置、开机问候、午饭、下班、深夜、保存成功等）各写几句，和固定台词混着用，按账号存在浏览器。提到天气时段的类别 2 小时过期、其余 24 小时；不该带天气的类别由代理过滤。
- **记忆**：分两层，都按账号存在浏览器。近期原文（最近 28 条，带时间）只发当前这段对话的最近 8 条：两句间隔超过 30 分钟（`SESSION_GAP_MS`）就算新的一段，之前的原文不再发。长期摘要（硬上限 800 字）由 DeepSeek 合并（后台运行，准确比快重要；同一组带日期的对话各压 6 次，DeepSeek 6 次全对，Qwen 只有 2 次，错在留下已过去的安排或删掉还没到的）：离开原文窗口的记录攒够 8 条，或那段对话结束（30 分钟没再说话、或下次打开页面），就并入摘要；`mergedAt` 记到哪条为止，同一条不重复压缩。摘要保留称呼和个人习惯、还没到的安排（请假、出差、会议等）、偏好和统计口径、未完成事项，不记查到的数字，闲聊不记；每条旧对话带日期，“下周三”这类说法换成具体日期，已过去的安排删掉。实测把前一天的对话原文带进今天的闲聊，Qwen 会沿用旧回复的口吻，回答缩成“嗯？”“……”，还会编天气。
- **台词与点评的上下文**：即时台词（戳、闲置、问候等）只带人设、心情和时间天气，不带记忆和对话，批量生成后存起来，触发时不调模型。页面点评走闲聊接口，带页面摘要和记忆。
- **蹦迪彩蛋**：`useFatfishDisco.ts` 数连戳（人形或收成球都算），相邻两下间隔不超过 1.25 秒；「戳×N」显示的就是这个数，满 100 变金色并带小火苗。过了 100 可以接着戳，停手 0.7 秒后播放 `public/fatfish/easter/` 里的整曲，页面按音频时间同步跳动（顶栏弹跳、侧栏左右摇、主体轻轻起伏、大肥鱼跳得最高，四角彩灯随拍闪，重拍最亮；系统开启「减少动态效果」时只微动）；Esc、切走标签页或播完即停，配乐在触发时才加载。前两下仍是原本的单击、双击开聊天、拖拽和右键，第三下起才归连戳。第一次成功开蹦后在本机记下 `fatfish-disco-unlocked`，大肥鱼会提示一句，之后右键菜单多出「蹦迪」，点一下直接开跳，不用再戳。
- **节奏舞台**：蹦迪时点「进入节奏舞台」打开 `FatfishDiscoStage.vue`，铺满页面、背景半透明，后面页面照样跳，不请求浏览器全屏。玩法同经典炫舞：每组先出一排箭头，按顺序敲方向键，按错整组清空；敲完等光标走到黄点按空格，按偏差判 PERFECT / GREAT / GOOD / BAD（±50 / 100 / 150 / 220 毫秒），没敲完或没按算 MISS，PERFECT / GREAT 连起来算连击。每个乐句最后一组标「长按」：黄点时按住空格撑过整小节，松早降为 BAD。敲完当前组会提前显示下一组。屏幕下方的按键也能点、空格键能按住。判定旁提示早了 / 晚了，敲键和判定有轻微合成音效（Web Audio，不加素材）；连击到 5 起控制台发金光（FEVER），每满 10 连击弹一次大字；进入主歌、推进、高潮时横幅扫过。中途「收起舞台」再进来，分数接着算，收起期间过去的组记为跳过、不算 MISS。播完评级盖章，配一句大肥鱼的评语，并显示得分、最高连击、长按完成数和各判定数，可再来一曲；本机最高分存在 localStorage 的 `fatfish-disco-best`，不写业务数据。
  - 谱面贴着这首歌排：从音频实测 129.7 BPM、首个小节线 1.564 秒，每 8 小节一个乐句（第 41–43 小节是 3 小节短句），乐句末那一小节能量下沉，正好做长按。每组两小节，节拍点都在小节线上；箭头数按段落递增（前奏 3、主歌 4、推进 5、高潮 6），同一段里各乐句的箭头组重复、隔句左右镜像，跟着音乐的重复走。数据和判定在 `discoRhythm.ts`，全部按音频当前时间计算；成绩只在页面内，不写业务数据。换歌要重新测 BPM、首小节和乐句末小节。

## 安全边界

- 没有直接改 / 删 / 提交数据的工具。宠物能像用户一样点页面，但页面因此发出的写请求都先暂停，等用户在卡片上放行（「本轮都放行」只管当前这一轮，不含删除）。这是浏览器里的一道确认，不是服务端授权：拦不到的通道见上文「写请求拦截」，真正的权限仍以系统接口自己的校验为准；填表建议只写到页面控件，由用户点卡片；自动保存页会由页面自己持久化（卡片提前标明）。密码类输入框不代填。
- 回答里说“点卡片下载 / 已生成 Excel”但本轮没有生成卡片时（以工具结果里前端回报的 `"proposal_created": true` 为准，调了出卡片的工具但失败了不算），代理删掉这些话，或改成如实说明没生成，不把假下载话术交给用户。本轮操作页面触发了被拦下的写请求时，屏幕上确实有确认卡片，也放行。指向前几轮卡片的说法，只有前端报告屏幕上确实还有待点的卡片（请求里的 `openCards`）时才放行；不看对话记录，因为前一轮的回答本身就可能是空口声称。模型的上下文里也带着这份卡片清单。闲聊模型若声称已填写、已导出，或自称“没法导出”，这句改由 agent 直接回答。这两处只核对说法和实际有没有生成卡片，不额外调用模型。
- 密码框与敏感字段名不送模型；正文打码邮箱和大陆手机号；焦点字段同样打码。
- `pet-proxy/logs/agent_trace.jsonl` 含业务内容，已在 `.gitignore`；超过约 5 MB 轮转。

素材署名与许可证见 `public/fatfish/ATTRIBUTION.txt`。
